# 採用雙軌圖鑑收集與跨題型結構化救援案件

舊版冒險島依賴兩項僅適用於九九乘法的設計：81 格「9×9 乘法寶石牆」與以字串 `'a×b'` 存放錯題的 `rescueQueue`。然而三位數加減法、規律跳數與動態生成的生活應用題有數以萬計的數字組合，無法用固定乘法格窮舉，也不存在口訣表對應的單純鍵值。

我們決定採用「雙軌圖鑑」架構：完整保留經典的 81 格「9×9 乘法寶石牆」，同時並行新增涵蓋加減法、生活應用題與規律位值的「數學技能圖鑑」（由約 24 張主題技能卡組成，依無失誤答對累積進階為銅卡、銀卡、金卡）與「魔王與故事收集冊」。此外，將「求救小精靈」的資料模型升級為結構化「救援案件（Rescue Case）」，完整封裝題型標籤、數字與模板參數快照，並設定佇列上限為 18 筆（超出時依先進先出淘汰最舊紀錄），讓所有海域與題型的錯題都能在求救特訓中精準重現。

## Considered Options

- **僅乘法保留收集牆，加減與應用題不設圖鑑**：會讓新海域只剩過關星星，長期收集成就感遠遜於九九乘法奇幻群島。
- **全面轉為過關隨機掉落貼紙**：過度依賴隨機抽獎感且稀釋學習回饋，也會破壞既有 81 格寶石牆的完整掌握意義。

## Consequences

- 所有題型生成器均須實作一致的技能標籤（`skillTag`）與可序列化救援快照（`rescueSnapshot`）契約，並確保兩步驟應用題與迷你直式題在求救模式中可完整還原。
- 81 格寶石牆的點亮邏輯與補完特訓保持獨立不變，舊存檔的寶石點亮進度無須轉換公式即可繼續沿用。
