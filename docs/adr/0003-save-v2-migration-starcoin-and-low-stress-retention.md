# 採用 v2 存檔無縫遷移、單一星星幣經濟與低壓力耐玩設計

隨著關卡由 15 關擴增至 45 關並加入三部位裝扮、秘密樹屋、精靈親密度、每日冒險委託與無盡試煉塔，舊版 `math_mul_quest_v1` 的扁平結構已不敷使用；同時本產品核心使用者為國小二年級學童，遊戲經濟與留存機制必須兼顧純前端離線運作與低挫折感。

我們決定採用獨立版本化的 `math_adventure_v2` 存檔鍵，首次載入時偵測 `math_mul_quest_v1` 並執行自動無縫遷移（完整保留舊星等至九九乘法奇幻群島、81 顆寶石、5 隻守護小精靈、8 款造型歸位與 10 枚徽章，將舊救援字串轉為救援案件，並贈與老探險家歡迎星星幣；原始 `v1` 鍵保留不刪作為安全備份），同時在家長設定視窗新增 JSON 匯出與匯入備份功能。在耐玩與經濟設計上，明確採行單一貨幣「星星幣」、不斷簽的「7 天累積制冒險印章本」、以及「無倒數計時的 3 愛心無盡試煉塔（每 5 層守塔小魔王回 1 愛心）」。

## Considered Options

- **大改版直接重置存檔**：會導致既有孩子辛苦點亮的 81 格寶石牆與星星紀錄消失，嚴重傷害信任。
- **多貨幣系統（金幣＋鑽石＋體力券）**：增加低年級認知負擔並帶有商業手遊課金感，偏離正向學習初衷。
- **限時競速爬塔與嚴格連續簽到歸零**：計時壓迫容易誘發兒童亂猜，漏簽一天歸零則易帶來強烈挫折與哭鬧。

## Consequences

- `normalizeSaveData` 與 `migrateV1ToV2` 須成為純函式領域層的核心守門員，任何版本遷移與 JSON 匯入皆須通過結構驗證與防護測試。
- 經濟平衡須區分首通獎勵、每日首 3 次重玩練習獎勵與超過上限後的象徵性鼓勵幣，防止反覆刷最簡單關卡破壞商店與樹屋節奏。
