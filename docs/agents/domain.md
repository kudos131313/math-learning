# Domain Docs

本文件說明工程技能在探索程式碼庫時，應如何讀取與遵循本專案的領域文件。本專案採用**單一語境（single-context）**配置。

## 探索程式碼前，請先讀取

- 根目錄的 **`GLOSSARY.md`**
- **`docs/adr/`**：讀取與即將修改區域相關的架構決策紀錄（ADR）

若上述檔案或目錄尚不存在，請**靜默繼續**，不要提醒缺少這些檔案，也不要主動要求先建立。`/domain-modeling` 技能（可經由 `/grill-with-docs` 與 `/improve-codebase-architecture` 觸發）會在術語或架構決策實際定案時延遲建立這些檔案。

## 檔案結構

單一語境（single-context）儲存庫配置：

```text
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
└── src/
```

## 遵循詞彙表的領域術語

當你的輸出提及領域概念（包含議題標題、重構提案、假設、測試名稱）時，請使用 `GLOSSARY.md` 中定義的標準術語，不要漂移到詞彙表已排除的同義詞。

若需要的概念尚未出現在詞彙表中，這代表兩個可能之一：你正在創造專案未使用的用語（請重新考慮），或是詞彙表確實存在缺口（請記錄下來交由 `/domain-modeling` 補齊）。

## 標記 ADR 衝突

如果你的輸出與既有的 ADR 相互矛盾，請明確指出而非默默覆蓋：

> _與 ADR-0007（決策標題）相衝突，但值得重新討論，因為……_
